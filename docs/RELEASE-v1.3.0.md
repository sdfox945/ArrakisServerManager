# Arrakis Server Manager v1.3.0 — Custom Configuration Management

The final metadata refinement keeps version 1.3.0 and schema 1. Example Value and User-Defined Default have separate labels/help/errors; user defaults are distinct from engine defaults and reset only Proposed Value. Manage Definition locks identity in its fixed header and emphasizes metadata-only behavior. Type-specific fields are conditional, inactive buffers are explicitly excluded rather than silently erased, and invalid forms cannot save. All original 312 scenarios remain; **334/334 tests pass, including 88 native WPF workflows**, with zero Release warnings/errors. The original candidate and ZIP remain recoverable; the accepted candidate is retained under packages-v1.3.0-metadata-refinement. The final distribution under packages-v1.3.0-final uses the same accepted application binaries with finalized documentation.

Developed on feature/v1.3-custom-config from published v1.2.0 commit 44025bed6270170a75cc95c293b31e09a20ddad2. The user has accepted the Custom Configuration Management feature and final metadata refinements. Release finalization establishes the local commit, fast-forwarded main and annotated v1.3.0 tag. Pushing or GitHub publication requires separate approval; no Nexus distribution or production operation is part of finalization.

The visual editor now resolves built-in definitions, persistent user metadata and safely discovered active scalars from the authoritative draft. Unknowns retain text and unknown provenance/ranges/defaults. Collections, duplicate or malformed identities, complex values and sensitive keys remain raw-only. Friendly names and dynamic categories include all sources; section/key identity stays exact and searchable/copyable.

A native guided Add Variable window validates supported-file identity, existing/new section, exact key, friendly name, type/value, category, optional metadata and literal preview. Confirmation persists metadata and inserts only the explicit draft change. Manage/Remove Definition, import/export review, atomic catalog storage/recovery/migration, Demo isolation and the persisted resizable editor are included. Metadata-only actions never dirty or rewrite an INI. Built-in validation and DifficultyLevel=Custom protection remain authoritative.

ConfigurationDraft extends its permitted visual intents through validated registered definitions or safely resolved existing scalars. It never trusts arbitrary UI-supplied validation metadata. The original snapshot/hash, explicit intent replay, frozen review payload, concurrency/backup/BusyBox lock/atomic rollback/readback and durable unknown outcomes remain. General sensitive INI-line redaction is strengthened without altering raw document bytes. The independent GitHub updater is retained; only release metadata/test fixtures advance to v1.3.0.
