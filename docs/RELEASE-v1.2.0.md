# Arrakis Server Manager v1.2.0 — application-update stable baseline

The final dialog UX refinement keeps version 1.2.0. Versions/availability stay fixed above one scrollable plaintext release-information panel; progress, cancellation/failure/verification and primary actions stay fixed below. No-update states hide empty download controls. Cancellation includes its percentage, failure enables Retry and copyable diagnostics, verified completion changes the primary action to Download Again, and manual installation help is collapsed. The underlying discovery, SemVer, HTTP/redirect/timeouts, download/partial/SHA/reuse, cache, preferences, Demo isolation and server-safety services are unchanged from the manually accepted candidate.

Developed from verified main baseline `549669d31af3c5120aa3466f0d39d9244259dfcc` on `feature/v1.2-updates`. The user accepted update discovery, cancellation, verified-download behavior and the final dialog refinement. Release finalization establishes a local commit, fast-forwarded main and annotated v1.2.0 tag; pushing and GitHub publication require separate approval. No existing public asset is replaced.

The new application-update subsystem is independent of Funcom server-update commands and the server operation/reconciliation coordinator. It adds a dynamic version/footer, cached anonymous stable-release checks, an opt-out preference and forced manual check, a plaintext details dialog and a cancellable SHA-256-verified portable ZIP downloader. Server gateways, config writer/rollback/conflict checks and durable server safety guards are preserved.

Repository identity is fixed once in Core. Installed version comes from Desktop assembly metadata. All remote tags, release pages, asset IDs/names/URLs/sizes/digests, redirects and cached metadata are validated. File paths cannot be derived from arbitrary attachments. ZIPs are streamed to unique partials, size/hash checked and finalized without extraction/execution, overwrite of existing corrupted files, elevation or automatic replacement/restart. Current operational limits, security bounds, timeouts, residual trust limits and installation steps are in APPLICATION-UPDATES.md.

Demo includes all eight requested scenarios through in-memory HTTP responses and inert local ZIP fixtures. The server Demo controls and application-update Demo controls are separate. Network failure cannot create a false Up to date state or mark a download verified; application update activity cannot create/clear server unknown outcomes. Automatic checks wait for rendering, operate without Hyper-V/server connectivity and never run during Demo against real GitHub.

All 159 previous regressions remain registered. New offline tests cover semantic versions/assembly detection, stable metadata and invalid identities, rate limits/timeouts/caches, streaming/progress/cancellation, checksum fallback/mismatch, existing files/destination safety, redirect/size bounds, no extraction/execution and actual WPF footer/settings/modal/download workflows. Final validation retains all 243 earlier cases: 256/256 automated tests, including 58 native WPF workflows. Release builds have zero warnings/errors. The extracted self-contained package passes the six-page Demo smoke plus isolated update scenarios. Earlier live GitHub discovery read only the existing v1.1.2 metadata; future-release/download scenarios are isolated simulations, not a real future public release. Finalization evidence and hashes accompany the publication-readiness report.

Safe manual acceptance: first use Launch Demo.cmd. Check the dynamic version, select each app-update scenario in Tools, open the footer dialog, inspect literal notes and endpoints, download/cancel a fixture and verify failure/success states. Confirm only a folder/path is offered after SHA verification. Turn automatic checks off and relaunch; confirm no automatic request, then manually check. In ordinary Live mode, checking GitHub alone requires no server operation; v1.2.0 may be ahead of the currently published v1.1.2 and should offer no downgrade. Do not exercise Funcom/server lifecycle/database/resource/update controls for this acceptance.

This release does not add an installer, executable signature or unattended self-updater. GitHub metadata hashes are not independent publisher signatures. The previously accepted fixture provenance/third-party boundary remains documented; no stable history or prior output is rewritten. The WaterExtractionRate correction remains user-observation-based, without a new independent gameplay claim. All existing live-acceptance limitations remain in force.
